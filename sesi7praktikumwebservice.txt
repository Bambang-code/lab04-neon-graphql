LAB 07
Implementasi OAuth2
Melindungi API yang sudah Anda bangun sejak lab 04 — kali ini hanya pengguna yang sudah login lewat GitHub yang boleh menjalankan mutation seperti createProduct.

Durasi 100 menit
Format Praktikum Berkelompok
Terkait Lab 04-05 — GraphQL Sederhana
Kaitan dengan lab sebelumnya: Lab ini melindungi endpoint yang sudah ada dari lab 04-05 (GraphQL server Anda). Anda tidak perlu membuat sistem login dari nol — cukup manfaatkan OAuth App milik provider (GitHub) yang sudah menangani autentikasi pengguna untuk Anda.
Tujuan Pembelajaran
01
Mahasiswa mampu menjelaskan alur OAuth2 Authorization Code secara praktis, bukan cuma teori.
02
Mahasiswa mampu mendaftarkan OAuth App di GitHub dan mendapatkan Client ID & Client Secret.

Materi Singkat
Alur OAuth2 Authorization Code
1. Redirect ke Provider
Aplikasi Anda mengarahkan pengguna ke halaman login GitHub, membawa client_id dan redirect_uri aplikasi Anda.

2. Pengguna Login & Memberi Izin
Pengguna login di GitHub (bukan di aplikasi Anda) dan menyetujui akses yang diminta — aplikasi Anda tidak pernah melihat password pengguna.

3. GitHub Redirect Kembali dengan Authorization Code
GitHub mengarahkan pengguna kembali ke redirect_uri aplikasi Anda, membawa satu kode sementara (code) di URL.

4. Tukar Code dengan Access Token
Server Anda (bukan browser pengguna) menukar code tersebut dengan access token lewat request langsung ke GitHub — inilah bagian yang membutuhkan client_secret, dan sebabnya harus dilakukan di server.

5. Buat Sesi/JWT Sendiri
Access token GitHub dipakai sekali untuk mengambil profil pengguna, lalu aplikasi Anda menerbitkan JWT-nya sendiri untuk dipakai melindungi resolver.

Langkah Praktik
Mengimplementasikan Login & Melindungi Resolver
01
Daftarkan OAuth App di GitHub
Buka GitHub → Settings → Developer settings → OAuth Apps → New OAuth App. Isi Authorization callback URL dengan URL deployment Anda dari lab 04, misalnya https://nama-app.onrender.com/auth/callback. Simpan Client ID dan Client Secret yang diberikan.

02
Buat Endpoint Login
app.get('/auth/login', (req, res) => {
  const url = \`https://github.com/login/oauth/authorize?client_id=${process.env.GITHUB_CLIENT_ID}&redirect_uri=${process.env.CALLBACK_URL}\`;
  res.redirect(url);
});
03
Buat Endpoint Callback & Tukar Token
app.get('/auth/callback', async (req, res) => {
  const { code } = req.query;

  const tokenRes = await fetch('https://github.com/login/oauth/access_token', {
    method: 'POST',
    headers: { 'Accept': 'application/json', 'Content-Type': 'application/json' },
    body: JSON.stringify({
      client_id: process.env.GITHUB_CLIENT_ID,
      client_secret: process.env.GITHUB_CLIENT_SECRET,
      code
    })
  });
  const { access_token } = await tokenRes.json();

  const userRes = await fetch('https://api.github.com/user', {
    headers: { Authorization: \`Bearer ${access_token}\` }
  });
  const githubUser = await userRes.json();

  const jwt = require('jsonwebtoken');
  const token = jwt.sign({ username: githubUser.login }, process.env.JWT_SECRET, { expiresIn: '1h' });

  res.json({ token }); // tampilkan token ke pengguna
});
04
Lindungi Resolver Mutation
Verifikasi JWT lewat context Apollo Server, lalu cek di resolver yang butuh proteksi (mis. createProduct dari lab 05):

// di konfigurasi Apollo Server
context: ({ req }) => {
  const authHeader = req.headers.authorization || '';
  const token = authHeader.replace('Bearer ', '');
  try {
    const user = jwt.verify(token, process.env.JWT_SECRET);
    return { user };
  } catch {
    return { user: null };
  }
}

// di resolver createProduct
createProduct: async (_, { input }, context) => {
  if (!context.user) {
    throw new Error('Unauthorized: silakan login terlebih dahulu');
  }
  // ...lanjutkan seperti resolver lab 05
}
05
Uji Alur Lengkap
Buka https://nama-app.onrender.com/auth/login di browser, login dengan akun GitHub, salin JWT yang ditampilkan. Di Apollo Sandbox, tambahkan header Authorization: Bearer <token>, lalu coba jalankan createProduct — bandingkan hasilnya dengan mencoba tanpa header tersebut.

Catatan Keamanan
client_secret dan JWT_SECRET wajib disimpan sebagai environment variable (bukan ditulis langsung di kode), dan jangan pernah di-commit ke GitHub. Ini murni untuk latihan kelas — untuk aplikasi produksi sungguhan, pertimbangan keamanan tambahan (rate limiting, refresh token, dst) masih diperlukan.
